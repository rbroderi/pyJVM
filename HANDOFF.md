### Known Windows gaps
- java.nio-backed `os` functions other than `stat` report errors errno-style (`[Errno 2] ...`) where CPython on Windows reports `[WinError N] ...`.
- `O_TEXT` descriptors do binary I/O (no CRLF translation); `os.open` without `O_BINARY` is binary here.
- `_winapi` (process/handle subset: CreateProcess with STARTUPINFO and handle_list, CreatePipe, DuplicateHandle, Wait*, GetExitCodeProcess, TerminateProcess, GetStdHandle, GetFileType, OpenProcess, NeedCurrentDirectoryForExePath, ...) and `msvcrt` (`get_osfhandle`, `open_osfhandle`, `setmode`, `Get/SetErrorMode`) exist, so `subprocess` works for native executables. fd <-> HANDLE bridge: `IoFd.Fd.handle`; pipe ends and `open_osfhandle` descriptors are HANDLE-backed (`nativeIo`, ReadFile/WriteFile); `get_osfhandle` of a file descriptor opens a second (shadow) handle on the path at the channel's offset (java.nio does not expose its handle). `nt.pipe`, `nt.dup2` and `nt.putenv`/`unsetenv` (`_wputenv_s`, so the CRT environment and child processes see the change, like CPython) are real. Overlapped I/O, named pipes and events now exist (wave 2). Not implemented: CopyFile2/LCMapStringEx in `_winapi`, `_overlapped` phase C (see wave 2), console and `locking` functions in `msvcrt`, text-mode translation for `setmode(O_TEXT)`, `get/set_inheritable` (still placeholders on Windows; real on Linux since N0 ticket 4). POSIX `pipe`/`dup2` exist since N0 ticket 6 (kernel descriptors).
- Absent like in posix: `spawnv`/`execv`/`system`/`startfile`, DLL directories, `listdrives`/`listvolumes`/`listmounts`, the ntpath accelerators (`_path_normpath`, `_path_splitroot_ex`, `_path_is*`, `_getvolumepathname`; ntpath falls back to Python).
- **Windows:** `get_inheritable`/`set_inheritable`, `get_blocking`/`set_blocking` and `umask` (the shared `PosixFiles` registrations; the `getuid` family is not exposed in `nt`) are still placeholders, against the no-placeholders rule; implement or remove them. On Linux (kernel descriptors, N0 tickets 4 and 6) they are real (`PosixOsFds`); the placeholders remain only on Windows and under `PYJVM_POSIX_FDS=nio`.
- signal: a handler's frame argument is None; `os.kill` of another pid fails. Interactive pdb is not verified.
- pyJVM's compressed zlib bytes differ from CPython 3.14+ on Windows (CPython links zlib-ng there); the cases compare round trips, not bytes.
