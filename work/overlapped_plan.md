# Plan: real `_overlapped` for pyJVM on Windows (written by a fable planning agent, 2026-11-15)

Scope for this round: Phase A + Phase B. Phase C is a later, separate plan.

## 1. Scope
Key finding: `ProactorEventLoop.__init__` calls `socket.socketpair()` (`proactor_events._make_self_pipe`; on Windows this is `socket._fallback_socketpair`: AF_INET listener on 127.0.0.1, non-blocking connect, accept, getsockname/getpeername check), then `signal.set_wakeup_fd(csock.fileno())`; `run_forever` reads the pair with `proactor.recv` -> `Overlapped.WSARecv`; `call_soon_threadsafe` does `csock.send(b'\0')`. So no loop can be constructed without a real loopback TCP socket.
- Phase A: `_overlapped` with IOCP/events/waits/pipes fully real, socket methods absent. Gives `import asyncio` (fixes unittest_mock_basic) and direct `_overlapped`/`_winapi` use.
- Phase B: real minimal Winsock `_socket` on Windows (stream sockets, IPv4/IPv6, what socketpair + self-pipe need) + `Overlapped.WSARecv/WSARecvInto/WSASend` + `signal.set_wakeup_fd` accepting a socket. Gives asyncio.run, call_soon/timers/run_until_complete/call_soon_threadsafe/run_in_executor, create_subprocess_exec with pipes, start_serving_pipe/create_pipe_connection.
- Phase C (later): AcceptEx, ConnectEx, DisconnectEx, TransmitFile, WSAConnect, BindLocal, WSARecvFrom(Into), WSASendTo, getaddrinfo -> asyncio TCP/UDP. Until then these names stay ABSENT (project rule), so create_server/open_connection fail with AttributeError.

## 2. Python-visible surface
3.13 and 3.15 identical in names/signatures (`git diff v3.13.18 HEAD -- Modules/overlapped.c`); only socket-only BindLocal ValueError text and the dealloc unraisable message differ. No LangVersion gates. All args positional-only except `Overlapped(event=...)`.

`_overlapped` functions (Phase A): `CreateIoCompletionPort(handle, port, key, concurrency)->int`, `GetQueuedCompletionStatus(port, ms)->None | (err, transferred, key, address)`, `PostQueuedCompletionStatus(port, nbytes, key, address)`, `RegisterWaitWithQueue(Object, CompletionPort, Overlapped_address, Milliseconds)->wait handle`, `UnregisterWait(h)`, `UnregisterWaitEx(h, Event)`, `CreateEvent(EventAttributes, ManualReset, InitialState, Name)` (non-None attributes: `ValueError("EventAttributes must be None")`), `SetEvent(h)`, `ResetEvent(h)`, `FormatMessage(code)` (strip trailing whitespace only, NOT dots; failure: `"unknown error code %u"`; do not reuse `WindowsNative.message`, which strips dots).

Constants: ERROR_IO_PENDING 997, ERROR_NETNAME_DELETED 64, ERROR_OPERATION_ABORTED 995, ERROR_SEM_TIMEOUT 121, ERROR_PIPE_BUSY 231, ERROR_PORT_UNREACHABLE 1234, INFINITE 0xFFFFFFFF, INVALID_HANDLE_VALUE 2**64-1, NULL 0, SO_UPDATE_ACCEPT_CONTEXT 0x700B, SO_UPDATE_CONNECT_CONTEXT 0x7010, TF_REUSE_SOCKET 2.

`Overlapped(event=INVALID_HANDLE_VALUE)`: default creates a manual-reset event; asyncio always passes NULL. Attributes: `address` (int), `pending` (bool: Internal==STATUS_PENDING(0x103) and type != NOT_STARTED), `error` (int), `event` (int). Methods Phase A: `cancel()`, `getresult(wait=False)`, `ReadFile(handle, size)`, `ReadFileInto(handle, buf)`, `WriteFile(handle, buf)`, `ConnectNamedPipe(handle)->bool`, `ConnectPipe(addr)->handle` (CreateFileW GENERIC_READ|WRITE, OPEN_EXISTING, FILE_FLAG_OVERLAPPED). Phase B adds `WSARecv(handle, size, flags=0)`, `WSARecvInto(handle, buf, flags)`, `WSASend(handle, buf, flags)`.

Semantics from overlapped.c: type states NONE / NOT_STARTED / op; second op: `ValueError("operation already attempted")`; getresult on NONE: `ValueError("operation not yet attempted")`, on NOT_STARTED: `ValueError("operation failed to start")`. Start results: SUCCESS/MORE_DATA/IO_PENDING -> None; ReadFile BROKEN_PIPE(109) -> set Internal=0 (+SetEvent if hEvent) and raise; other error -> type=NOT_STARTED and raise. ConnectNamedPipe: ERROR_PIPE_CONNECTED(535) -> mark completed, return True; SUCCESS/IO_PENDING -> False. getresult: GetOverlappedResult(handle, ov, &n, wait); ok for SUCCESS, MORE_DATA(234), and BROKEN_PIPE when type is read/readinto; result = bytes[:n] for read, n for readinto/write, None for ConnectNamedPipe; sets `error`. cancel: no-op if NOT_STARTED; CancelIoEx only if still pending; ignore ERROR_NOT_FOUND(1168). GQCS: lpOverlapped NULL and err==WAIT_TIMEOUT(258) -> None, NULL otherwise -> raise; else tuple even when err != 0. Errors: `SetFromWindowsErr`: winerror 1225 -> ConnectionRefusedError, 1236 -> ConnectionAbortedError, else `WindowsNative.winError(code, null)` (add a `winError(type, code)` overload for the two forced types).

`_winapi` additions (WindowsWinApiModule.java): `CreateNamedPipe(name, open_mode, pipe_mode, max_instances, out_size, in_size, default_timeout, security_attributes)`, `CreateFile(name, access, share, sa, disposition, flags, template)` (sa must be NULL/0), `ConnectNamedPipe(handle, overlapped=False)` returning a `_winapi.Overlapped` when overlapped=True (`asyncio.windows_utils.pipe` uses `ov.GetOverlappedResult(True)` -> `(transferred, err)`; also `cancel()`, `getbuffer()`, `event`), `CreateEventW`, `SetEvent`, `ResetEvent`. Constants: FILE_FLAG_OVERLAPPED 0x40000000, FILE_FLAG_FIRST_PIPE_INSTANCE 0x80000, PIPE_ACCESS_DUPLEX 3, PIPE_ACCESS_INBOUND 1, PIPE_READMODE_MESSAGE 2, PIPE_TYPE_MESSAGE 4, PIPE_WAIT 0, PIPE_UNLIMITED_INSTANCES 255, NMPWAIT_WAIT_FOREVER 0xFFFFFFFF, OPEN_EXISTING 3, ERROR_PIPE_BUSY 231, ERROR_IO_PENDING 997, ERROR_OPERATION_ABORTED 995, ERROR_NETNAME_DELETED 64, ERROR_SEM_TIMEOUT 121, ERROR_PIPE_CONNECTED 535, ERROR_ALREADY_EXISTS 183, FILE_GENERIC_READ 0x120089, FILE_GENERIC_WRITE 0x120116. Still missing afterwards (multiprocessing only, out of scope): overlapped ReadFile/WriteFile in _winapi, PeekNamedPipe, WaitNamedPipe, SetNamedPipeHandleState, BatchedWaitForMultipleObjects. Update the class javadoc listing what is absent. Verify every constant against CPython on this machine.

## 3. Design
New files in runtime/pyjvm315/runtime/:
- `WindowsIocp.java`: FFM layer (WindowsHandles.java conventions: `k32(...)` handles with CALL_STATE, `winError(lastError(st), null)`, `rethrow`). CreateIoCompletionPort, GetQueuedCompletionStatus, PostQueuedCompletionStatus, CreateEventW, SetEvent, ResetEvent, RegisterWaitForSingleObject, UnregisterWait, UnregisterWaitEx, CancelIoEx, GetOverlappedResult, ConnectNamedPipe, CreateNamedPipeW, overlapped ReadFile/WriteFile (own MethodHandles; do not reuse the blocking helpers), `calloc`/`free` from `Linker.defaultLookup()`.
- `WindowsOverlappedModule.java`: module + `Overlapped` class via `NativeTypes.define("_overlapped","Overlapped",null)`, `__new__` as SelectModule.pollNew does, `NativeTypes.method(...)`, state via `NativeTypes.newInstance/state`, properties via `cls.properties.put(name, new PyProperty(owner, javaGetter, null))` as WeakrefModule.java:146 does. Share `handle()`/`unsigned()` from WindowsWinApiModule (make package-private).
- Phase B: `WindowsSockets.java` (ws2_32 FFM with `Linker.Option.captureCallState("WSAGetLastError")`) and `WindowsSocketModule.java`.
Changed: `ImportSupport.java` (add `_overlapped` to WINDOWS_ONLY, NATIVE_NAMES, the create switch; Phase B: `_socket` -> WindowsSocketModule on Windows, StubModules.socket() stays for POSIX; keep `SelectModule.wsaStarted` set when _socket is created), `WindowsWinApiModule.java`, `WindowsNative.java` (winError overload), `SignalModule.java` (set_wakeup_fd), `StubModules.java` comment, STDLIB_STATUS.md regenerated, JVM_BACKEND.md note on Overlapped finalization.

Memory/lifetime: no Arena per object. `OvState` (plain Java, never references the PyInstance): `long ov` (calloc 32 bytes: Internal 0, InternalHigh 8, Offset 16, OffsetHigh 20, hEvent 24), `long buf, bufLen`, `Object target` (ReadFileInto bytearray), handle, type, error, `boolean orphaned, copied`. Native buffers are always calloc'd copies: ReadFile -> calloc(max(size,1)), copied to bytes on getresult; ReadFileInto -> native buffer of `IoUtil.bufferSize(buf)`, copied back once with `IoUtil.fill` on first successful getresult (document: data not visible earlier); WriteFile -> copy of `IoUtil.bytesLike`. Static `ConcurrentHashMap<Long,OvState> LIVE` keyed by OVERLAPPED address holds every started state the kernel may still own. A static `java.lang.ref.Cleaner` on each Overlapped PyInstance: if not pending (Internal != 0x103 or never started) -> CloseHandle(event), free ov+buf, remove from LIVE; if pending -> CancelIoEx, set `orphaned`, do NOT block and do NOT free. Orphans freed by a sweep (`Internal != 0x103`) at each `Overlapped()` creation and when GQCS dequeues their address. Documented deviation: no "still has pending operation at deallocation" RuntimeError/unraisable. Never free while Internal == STATUS_PENDING. Keep IOCP-associated orphans in LIVE until their packet is dequeued (freed-address reuse).

Threads: no GIL; blocking FFM calls (GQCS with timeout, GetOverlappedResult(wait)) called directly, holding no Java lock. OvState methods `synchronized(state)` except the blocking wait. GQCS out-params in a confined Arena per call.

Waits: `RegisterWaitForSingleObject(&h, obj, CB, ctx, ms, WT_EXECUTEINWAITTHREAD|WT_EXECUTEONLYONCE = 0x4|0x8)` with ONE global FFM upcall stub (`LINKER.upcallStub(..., Arena.global())`, `void(ADDRESS ctx, JAVA_BYTE fired)`); ctx is an id into `ConcurrentHashMap<Long,long[]{port, ovAddr}>`; callback removes the entry and calls PostQueuedCompletionStatus(port, fired, 0, ovAddr), catching all Throwables (an escaping exception kills the JVM). Map waitHandle->id so UnregisterWait/Ex drop un-fired entries. Keeps real UnregisterWait/Ex behaviour (asyncio relies on OSError winerror ERROR_IO_PENDING from them and on the Event being signalled). Fallback if the spike fails: one daemon Java thread per wait doing WaitForSingleObject then Post, with emulated wait handles and emulated ERROR_IO_PENDING.

Phase B sockets: WSAStartup once; `WSASocketW(af, type, proto, NULL, 0, WSA_FLAG_OVERLAPPED|WSA_FLAG_NO_HANDLE_INHERIT)`; methods: bind, listen, connect, _accept, getsockname, getpeername, setblocking, settimeout/gettimeout (None and 0 exact; positive timeouts via ws2_32 select), send, recv, close, detach, fileno, shutdown, setsockopt/getsockopt (int form), family/type/proto/timeout; everything else absent. Module constants must be the WINDOWS values on Windows (stub has Linux ones: AF_INET6 23, SOL_SOCKET 0xFFFF, SO_REUSEADDR 4, SO_ERROR 0x1007, SO_TYPE 0x1008, SOMAXCONN 0x7fffffff, ...; take from CPython on this machine). Errors: winError(WSAGetLastError); confirm 10035 maps to BlockingIOError in ErrnoModule.osErrorType. `set_wakeup_fd` on Windows: accept a socket handle (validate with getsockopt SO_TYPE, else keep WinError 6), store it, return the previous value, send one byte (signal number) when a signal is tripped. Make `select.select` work for real sockets on Windows via ws2_32 select (it currently can only raise).

## 6. Risks; verify first with spikes (small Java mains under a scratch dir, `java --enable-native-access=ALL-UNNAMED`)
1. Upcall from a Windows thread-pool wait thread (RegisterWaitForSingleObject + WT_EXECUTEINWAITTHREAD) on Java 25: works, does not block JVM exit, no stderr noise. Else the helper-thread fallback.
2. `captureCallState("WSAGetLastError")` on ws2_32 calls, and non-blocking connect/accept on loopback behaving as `_fallback_socketpair` expects.
3. asyncio has NEVER run on pyJVM: expect unrelated gaps (no `_asyncio` accelerator so pure-Python Task/Future, contextvars `Context.run`, `sys.get/set_asyncgen_hooks`, signal handling in `asyncio.Runner`, weakref sets). Try `asyncio.run(asyncio.sleep(0))` as soon as step 7 compiles.
4. GC-timed finalizers: `PipeHandle.__del__`/socket `__del__` run late or never; an unclosed write end can delay EOF (see the `WeakrefDelivery.collect()` hack in createProcess). Tests must close everything explicitly.
5. Freed-address reuse (see lifetime section).
6. Blocking GQCS(INFINITE) cannot be interrupted by Ctrl-C without the wakeup socket; check how SignalModule's safe-point delivery interacts with a thread parked in native code.
7. CPython `Modules/` is not in the sparse checkout of C:\Users\richa\workspace_local\cpython; read with `git show HEAD:Modules/overlapped.c` / `git show v3.13.18:Modules/overlapped.c` (same for `_winapi.c`, `socketmodule.c`).
